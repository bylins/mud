# Ведун — правка конфигов прямо в игре

`vedun` — встроенный редактор конфигурационных файлов движка. Он открывает `cfg/**.xml` как дерево,
даёт менять атрибуты и узлы с проверкой типов, а по сохранению сам перезаписывает файл и перечитывает
данные — без перезапуска сервера и без доступа к диску.

Редактор не знает про мир (зоны, мобов, предметы — это OLC) и не трогает код. Его дело — данные
механик: заклинания, умения, аффекты, лавки, гильдии, сообщения.

## 1. Как позвать

```
vedun                       список наборов, доступных вам по правам
vedun <набор>               список элементов набора
vedun <набор> <элемент>     правка элемента
```

Имя набора пишется **одним словом**. Подчёркивание есть ровно у трёх наборов — `obj_affects`,
`equipment_affects`, `room_affects`, — остальные слитно: `affects`, `spell`, `skillmsg`, `shopmsg`,
`pcrace`, `currencyname`. Отсюда частая ошибка: `vedun obj affects` даёт
`Vedun: unknown data set 'obj'`, потому что вторым словом редактор ждёт уже имя элемента. Правильно
`vedun obj_affects`.

Имя элемента можно писать в несколько слов: `vedun spell ледяной ветер` разрешится по полному
названию (а не по первому слову).

Для входа нужны две вещи: команда `vedun` в правах бога и доступ к конкретному набору — см. раздел 7.

## 2. Экран правки

```
Vedun [spell]  spell/talent_actions/action  *modified*  -- одно действие заклинания
 1) target      kTarFightVict   <enum EActionTarget>   на кого
 2) base        tag             <enum EActionBase>     от чего считается сила
 3) <trigger>                                          событие, запускающее действие
 4) <affects>                   2 шт.                  что накладывается
Select a number -- attribute = edit, <tag> = enter.
l) list   p) print   a) add child   d) delete child   m) move child   s) save   u) up   q) quit
```

Сверху — имя набора, путь по дереву (хлебные крошки) и пометка `*modified*`, если есть несохранённые
правки. Дальше таблицей атрибуты текущего узла и его дети, всё под общей нумерацией.

**Выбор по номеру:** номер атрибута — правка значения, номер узла `<тег>` — вход внутрь.

Пункты меню:

| | |
|---|---|
| `l` | список элементов набора |
| `p` | напечатать текущий узел целиком |
| `a` | добавить дочерний узел (показывается, только если схема разрешает здесь детей) |
| `d` | удалить дочерний узел |
| `m` | переставить дочерние узлы местами (`u`/`d` двигают выбранный, пустой ввод завершает) |
| `s` | сохранить |
| `u` | на уровень выше |
| `q` | выход (при несохранённых правках спросит: `s` сохранить и выйти, `a` уйти без сохранения, `c` отмена) |

## 3. Ввод значений

* **`?`** — показать список допустимых значений для поля-перечисления; значение можно выбрать номером
  из этого списка, а не печатать токен целиком.
* **Наборы флагов** переключаются номерами: вводишь номера членов, `d` применяет, `c` отменяет.
* **`.` или пустая строка** — отмена правки.
* **`~`** — удалить необязательный атрибут совсем (не «поставить пусто», а убрать). Атрибуты с
  `readonly="Y"` защищены.
* Значение проверяется по схеме сразу: неизвестный токен перечисления или число вне диапазона дают
  `Rejected: ...`, и правка остаётся открытой — можно ввести заново.

## 4. Создание и удаление элементов

Отдельной команды «создать» нет: если набрать `vedun <набор> <идентификатор>`, которого ещё нет, но он
годится этому набору как ключ, элемент откроется на правку и будет создан. Если ключ не годится,
редактор скажет `'...' is not a valid <набор> identifier (and matches no existing element)`.

Схема может запретить правку отдельных элементов — тогда `'...' is not editable (prohibited by its
scheme)`.

Дочерние узлы внутри элемента добавляются и удаляются пунктами `a` и `d`.

## 5. Сохранение

По `s` редактор:

1. **проверяет** собранное дерево загрузчиком набора — «сухой» разбор, без подмены рабочих данных;
2. пишет файл **атомарно** — во временный `.new`, затем переименованием;
3. **перечитывает** набор, то есть правка вступает в силу сразу.

В ответ приходит `Vedun: saved and reloaded.` Отдельный `reload` после этого не нужен.

Если проверка не прошла, приходит `Vedun: save refused -- <причина>` и приписка, что файл не менялся:
исходный файл при неудаче не рискует никогда.

## 6. Схемы `*.scheme`

Рядом с файлом данных может лежать сосед `<имя>.scheme` — он описывает редактору, что в этом файле
бывает: какие теги, какие у них атрибуты, какого типа (`int`, `float`, `string`, `enum<EElement>`,
наборы флагов), что только для чтения, какие узлы можно добавлять и какие элементы править нельзя. Из
схемы же берутся подсказки и описания, которые видно в таблице.

Схема необязательна. Без неё редактор всё равно работает, но поля становятся простыми строками: ни
проверки значений, ни подсказок, ни меню «добавить узел». Структуру в любом случае проверит загрузчик
при сохранении.

Схемы проверяются при старте сервера, и в сислог идёт строка вида:

```
Vedun scheme lint [affects]: 0 enum error(s), 0 undeclared tag type(s), 0 undeclared attribute(s).
```

Ненулевые числа означают, что схема разошлась с кодом: например, в ней объявлено перечисление,
которого в движке уже нет. Редактор от этого не падает, но подсказки в таких местах врут — схему надо
поправить.

## 7. Права

Задаются в `cfg/privilege.xml` на каждого бога:

```xml
<commands list="invis|vedun|wizhelp"/>
<vedun list="skillmsg|spellmsg|hitmsg|guildmsg|featmsg"/>
```

* в `<commands>` должна быть сама команда `vedun` — иначе в редактор не войти;
* в `<vedun>` перечисляются доступные наборы; `*` или `all` открывают любой;
* флаг `FullAccess` даёт все наборы сразу;
* владелец сервера правит всё без перечислений.

Список, который печатает `vedun` без аргументов, уже отфильтрован по вашим правам: чего там нет — то
вам и не открыть.

## 8. Чего редактор не откроет

Файл, у которого в корне стоит `vedun="false"`, редактор открывать отказывается. Так помечены
конфиги с многострочным форматированным текстом (`CDATA`): Ведун сохраняет файл целиком и переписал бы
такой текст как обычную строку, сломав разметку. Такие файлы правятся на сервере руками.

## 10. Частые ошибки

| Сообщение | Отчего |
|---|---|
| `unknown data set 'obj'` | забыто подчёркивание: нужно `obj_affects` |
| `you have no permission to edit '<набор>'` | набор не перечислен в `<vedun list=...>` ваших прав |
| `'...' is not a valid <набор> identifier` | опечатка в идентификаторе, либо такой ключ набору не годится |
| `'...' is not editable (prohibited by its scheme)` | элемент закрыт от правки схемой |
| `save refused -- ...` | загрузчик не принял дерево; файл не изменился, правки остались в сессии |
| `Rejected: ...` при вводе | значение не прошло проверку по схеме, правка осталась открытой |
