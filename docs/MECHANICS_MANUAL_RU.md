# Руководство по настройке механик BRusMUD

Этот документ описывает **настраиваемые данными** игровые механики движка: где лежит их
конфигурация, как её править и перезагружать «на лету», и что означает каждый параметр.

Правило движка: настраиваемая механика описывается конфигом в `cfg/mechanics/…`, грузится через
`CfgManager`, перезагружается командой `reload …` и (если у неё есть схема) правится редактором
`vedun`. Логику, которую держат в коде (например, влияние способностей-фитов), в конфиг не выносят —
такие места отдельно оговорены.

Оглавление:

- [Поднятие нежити (Animate Dead)](#поднятие-нежити-animate-dead)
- [Оживить скелет (костяная свита чернокнижника)](#оживить-скелет-костяная-свита-чернокнижника)

## Поднятие нежити (Animate Dead)

Механика конструктов чернокнижника: заклинание **«поднять труп»** превращает труп в подконтрольную
нежить. Тип нежити зависит от уровня трупа и мастерства заклинателя, число одновременно управляемых
существ ограничено «бюджетом управления», а характеристики поднятого существа масштабируются от силы
накладывания заклинания. Все эти параметры вынесены в один файл, чтобы гейм-дизайнеры могли их
балансировать без пересборки движка.

### 1. Где лежит и как применять

| | |
|---|---|
| Файл | `cfg/mechanics/animate_dead.xml` |
| Схема для `vedun` | `cfg/mechanics/animate_dead.scheme` |
| Идентификатор в `CfgManager` | `animate_dead` |
| Перезагрузка без рестарта | `reload animatedead` |
| Правка в игре | `vedun creature` (список), `vedun creature <vnum>` (правка тира) |
| Загрузка при старте | `MUD::CfgManager().LoadCfg("animate_dead")` в `db.cpp` (грузится при загрузке мира) |

Порядок работы дизайнера: правим `animate_dead.xml` (руками или через `vedun`) → `reload animatedead`
→ проверяем в игре. Изменения вступают в силу сразу для **новой** поднимаемой нежити.

> Файл — обычный ASCII/латиница (английские имена атрибутов), его можно править любым редактором.
> **Внимание:** в теле XML-комментариев `<!-- ... -->` нельзя использовать двойной дефис `--`
> (это запрещено спецификацией XML) — пишите одиночный `-`.

### 2. Структура файла

```xml
<animate_dead>
    <!-- бюджет управления = min(<skill>, budget_cap) - сумма весов удерживаемой нежити -->
    <control skill="kDarkMagic" budget_cap="75" />

    <creature vnum="0" id="kSkeleton" proto_vnum="3001" weight="8">
        <cost corpse_max_level="5" min_rating="0" />
        <scaling>
            <hp          beta="0.25" mode="mult" />
            <damage_dice beta="1.5"  mode="add"  cap="100" />
            <hitroll     beta="0"    mode="add" />
            <ac          beta="0"    mode="add" />        <!-- меньше AC = лучше; задайте cap= для нижней границы -->
            <skills      beta="0"    mode="add"  cap="200" />
            <saving      beta="0"    mode="add" />        <!-- все 4 спасброска; меньше = лучше -->
            <armor       beta="0"    mode="add" />
            <morale      beta="0"    mode="add" />
            <initiative  beta="0"    mode="add" />
        </scaling>
    </creature>

    <!-- остальные тиры, от слабого к сильному ... -->
</animate_dead>
```

Тиры (`<creature>`) перечисляются **от слабейшего к сильнейшему** — этот порядок и есть «лестница»,
по которой механика понижает выбор, когда сильный тир недоступен.

### 3. Блок `<control>` — бюджет управления

| Атрибут | Смысл |
|---|---|
| `skill` | Навык, задающий бюджет и «рейтинг» заклинателя. По умолчанию `kDarkMagic`. |
| `budget_cap` | Верхняя граница бюджета: даже при очень высоком навыке бюджет не превысит это значение. |

**Бюджет управления** = `min(навык, budget_cap) − Σ(вес уже удерживаемой нежити)`.

Каждый тир «стоит» свой `weight`. Пока в бюджете есть место под вес нового существа — его можно
поднять; если места нет даже под слабейший тир, поднятие срывается сообщением
«Вы не сможете управлять столькими последователями.».

> **Важно (скрытый порог входа):** вес слабейшего тира — это фактический минимальный навык, при
> котором можно поднять хоть кого-то. Если у слабейшего тира `weight=8`, то заклинатель с навыком
> ниже 8 не поднимет вообще ничего. Держите вес входного тира не выше навыка, ожидаемого у
> начинающего некроманта.

### 4. Тиры `<creature>` и блок `<cost>`

Атрибуты `<creature>`:

| Атрибут | Смысл |
|---|---|
| `vnum` | Индекс тира в конфиге (ключ для `vedun`); задаёт порядок лестницы. |
| `id` | Символьное имя тира, например `kSkeleton` (для списков и логов). |
| `proto_vnum` | VNUM моба-прототипа, который будет поднят. |
| `weight` | Стоимость одного такого существа в бюджете управления. |

Блок `<cost>` — условия доступности тира:

| Атрибут | Смысл |
|---|---|
| `corpse_max_level` | Наибольший уровень трупа-источника, дающий этот тир (полоса по уровню трупа). |
| `min_rating` | Наименьший «рейтинг» заклинателя, при котором тир разрешён (см. ниже). |
| `pick` | Относительные шансы выбора внутри общей верхней полосы (необязательный; `0`/отсутствует = одиночный тир). |

### 5. Как выбирается тир при поднятии

Когда игрок поднимает труп, тир определяется в три шага (`PickTier`):

1. **Полоса по уровню трупа.** Берётся слабейший тир, чей `corpse_max_level` покрывает уровень
   трупа. То есть слабый труп даёт слабую нежить, сильный — сильную.

2. **Случайный выбор внутри полосы.** Если несколько тиров делят одну верхнюю полосу
   (одинаковый `corpse_max_level`), между ними бросается жребий по весам `pick`. Так, например,
   один и тот же «высокоуровневый» труп с шансом 50/50 даёт «урончика» или «дыхателя».

3. **Гейт по рейтингу заклинателя.** Выбранный тир понижается по лестнице вниз, пока рейтинг
   заклинателя не дотянет до `min_rating` тира:

   ```
   рейтинг = уровень + псевдо-реморт + 4
   псевдо-реморт = max(0, (навык − SkillCapStart) / SkillCapIncrement)
   ```

   где `SkillCapStart` (порог навыка при 0 ремортов, обычно **80**) и `SkillCapIncrement`
   (прибавка кэпа навыка за реморт, обычно **5**) — константы движка. То есть рейтинг растёт от
   **навыка**, а не от числа ремортов: навык 80 → +0, навык 85 → +1, навык 90 → +2 и т.д.

   Пример: персонаж 30 уровня с навыком 80 → рейтинг = 30 + 0 + 4 = 34; при `min_rating=32` он
   пройдёт гейт и сможет поднимать верхние тиры.

После выбора тира срабатывает проверка бюджета (`FitUndeadTier`, шаг из раздела 3): если на
выбранный тир не хватает бюджета, он **понижается** до ближайшего тира, который влезает; если не
влезает даже слабейший — поднятие срывается.

### 6. Пример: почему «скелет», а не отказ

Персонаж «Чернок», 10 уровень, навык `kDarkMagic` = 10, поднимает труп 4 уровня:

1. Полоса: труп 4 уровня ≤ `corpse_max_level=5` скелета → выбран **скелет**.
2. Гейт: рейтинг = 10 + max(0, (10−80)/5) + 4 = 10 + 0 + 4 = 14 ≥ `min_rating=0` → скелет остаётся.
3. Бюджет: `min(10, 75) − 0 = 10`; вес скелета `8 ≤ 10` → скелет поднимается.

Второго скелета Чернок уже не удержит: остаток бюджета `10 − 8 = 2 < 8` → «Вы не сможете управлять
столькими последователями.». (Если бы вес скелета был `12`, как в первой версии, Чернок не поднял бы
даже одного — отсюда правило про «скрытый порог входа» из раздела 3.)

### 7. Масштабирование характеристик — блок `<scaling>`

Характеристики поднятого существа улучшаются относительно **прототипа** пропорционально
**компетентности накладывания** `C` (`SetupUndeadStats`). Каждая строка `<scaling>` — это одна
характеристика со своими параметрами:

| Атрибут | Смысл |
|---|---|
| `beta` | Коэффициент масштабирования. `0` = характеристика не меняется (берётся как у прототипа). |
| `mode` | `add` — прибавка; `mult` — множитель (см. формулы ниже). |
| `cap` | Граница результата. **`cap="0"` или отсутствие cap = нет ограничения** (без границы). Для `mode="mult"` cap ограничивает **множитель** (`значение ≤ прототип × cap`); для `mode="add"` — абсолютный **потолок** для «растущих» и **нижняя граница** для «убывающих» (AC, спасброски). |

Масштабируемые характеристики:

- **`hp`** — максимум HP (`mult` сохраняет пропорции тиров).
- **Урон** — три части броска прототипа `NdM+B` масштабируются по отдельности:
  - **`damage_dice`** — *число* костей (N, `damnodice`);
  - **`damage_size`** — *размер* кости / величина (M, `damsizedice`);
  - **`damage_bonus`** — плоская прибавка *+B* к каждому удару (дамролл моба).
- **`hitroll`**, **`armor`**, **`morale`**, **`initiative`** — «растущие».
- **`ac`**, **`saving`** (все 4 спасброска) — «убывающие» (меньше = лучше).
- **`skills`** — все умения, которые уже есть у прототипа, равномерно.

Характеристики `luck` нет намеренно — у мобов её не существует.

**Формулы.** Пусть `C` — компетентность (см. раздел 8):

- «Растущие» (`hitroll`, `armor`, `morale`, `initiative`, `skills`, `damage_dice`, `damage_size`,
  `damage_bonus`), `mode="add"`: `значение = прототип + round(beta · C)`, затем ограничивается сверху `cap`.
- «Убывающие» (`ac`, `saving`), где меньше = лучше, `mode="add"`:
  `значение = прототип − round(beta · C)`, затем ограничивается снизу `cap`.
- Здоровье `hp`, `mode="mult"`: `значение = прототип × min(1 + beta · C, cap)` — cap ограничивает
  **множитель** (например, `cap="2.0"` ⇒ не выше 2× прототипа). Сохраняет пропорции между тирами.
- `damage_dice` и `damage_size` дополнительно зажимаются в диапазон `1…100` (защита знаковых байтов
  `damnodice` / `damsizedice`).

Стартовые значения в конфиге: `hp beta=0.25 mode=mult cap=2.0` (до +25 % · C, потолок 2× прототипа —
≈ максимум до переработки) и `damage_dice beta=1.5 mode=add cap=25`. `damage_size`, `damage_bonus`
и остальные боевые характеристики поставлены на `beta=0` (выключены) — их можно включать и настраивать.

### 8. Что такое компетентность `C`

`C` — та же «сила накладывания», что и у прочих заклинаний: сумма вклада навыка и профильной
характеристики (для нежити это Мудрость):

```
C = skill_coeff + stat_coeff
skill_coeff = ( min(навык, 75)·low_bonus + max(0, навык−75)·hi_bonus ) / 100
stat_coeff  = max(0, мудрость − порог) · stat_weight / 100
```

Коэффициенты `low_bonus`, `hi_bonus`, `порог` и `stat_weight` берутся из блока `<potency_roll>`
заклинания `kAnimateDead` в `cfg/…/spells.xml` — то есть «крутизна» масштабирования настраивается
там, а `beta` в `animate_dead.xml` лишь задаёт, насколько сильно данная характеристика реагирует
на `C`.

Практически: `C` растёт с навыком Тёмной магии и Мудростью и для опытного некроманта имеет порядок
единиц. Поскольку точное значение зависит от `<potency_roll>`, подбирайте `beta` **опытным путём**:
выставьте значение, поднимите существо разными по силе заклинателями и посмотрите итоговые
характеристики (`vstat`/`stat` по мобу).

### 9. Практические рецепты

- **Добавить новый тир.** `vedun creature new` создаст запись с первым свободным `vnum`; заполните
  `id`, `proto_vnum`, `weight`, блок `<cost>` и `<scaling>`. Не забудьте про порядок лестницы: тир
  должен стоять между соседями по силе.
- **Разрешить более раннее поднятие сильного тира.** Уменьшите его `min_rating` и/или `weight`.
- **Ограничить «толпу».** Поднимите `weight` тиров или снизьте `budget_cap` — управляемых существ
  станет меньше. Держите `weight` сильнейшего тира равным `budget_cap`, если хотите «максимальный
  навык = ровно одно топовое существо».
- **Сделать существо крепче/сильнее.** Поднимите `beta` у нужной характеристики; для «убывающих»
  (AC, спасброски) обязательно задайте `cap` как нижнюю границу, иначе значение уйдёт в минус без
  предела.
- **Расширить/сузить полосу уровней трупа.** Меняйте `corpse_max_level`: тир получают все трупы с
  уровнем не выше указанного (и выше `corpse_max_level` предыдущего тира).

### 10. Типичные ошибки

- **Вес входного тира выше стартового навыка** → начинающий некромант не поднимает ничего и видит
  «слишком много последователей», хотя нежити у него нет. Держите `weight` слабейшего тира ≤
  ожидаемого навыка новичка.
- **`beta` у «убывающей» характеристики без `cap`** → AC или спасброски уходят в бесконечный минус.
- **Нарушен порядок лестницы** (`<creature>` не по возрастанию силы) → понижение по гейту и бюджету
  выберет «не тот» тир. Перечисляйте от слабого к сильному.
- **`--` в комментарии XML** → строгий парсер отвергнет файл; используйте одиночный дефис.
- **Правка `min_rating` под реморты** — не нужно: гейт считает псевдо-реморт из навыка, реморты
  напрямую не участвуют.

### 11. Что осталось в коде (не в конфиге)

- Влияние способностей-фитов (например, «Ярость Тьмы» / `kFuryOfDarkness`, дающая прибавку к
  характеристикам нежити) применяется в коде поверх конфигурационного масштабирования.
- Само разбиение на три шага выбора (полоса → жребий → гейт) и формулы масштабирования — в коде
  (`src/gameplay/mechanics/animate_dead.cpp`); конфиг задаёт только их **данные**.

## Оживить скелет (костяная свита чернокнижника)

Второе корпусное заклинание чернокнижника: **«оживить скелет»** поднимает из трупа костяного
прислужника. Со способностью **«костяной полководец»** доступны три особых вида, и вид называет сам
игрок: `колдовать 'оживить скелет' труп свирепого`. Без способности, с трупа ниже порога или с
нечеловекоподобного встаёт обычный скелет.

Виды описаны в том же `animate_dead.xml`, но **отдельным списком**: у них стоит
`spell="kAnimateSkeleton"`, и лестница «поднять труп» их не выбирает.

### 1. Где что лежит

| Что настраиваем | Файл |
|---|---|
| Виды скелетов: кубики, жизни, порог трупа | `cfg/mechanics/animate_dead.xml` (ярусы с `spell="kAnimateSkeleton"`) |
| Само заклинание: мана, стихия, цель, обработчик | `cfg/spells.xml`, `<spell id="kAnimateSkeleton">` |
| Круг и уровень заклинания, круг способности | `cfg/classes/pc_necromancer.xml` |
| Способность «костяной полководец» | `cfg/feats.xml`, `<feat id="kBoneCommander">` |
| Русские имена и сообщения | `cfg/messages/ru/spell_msg.xml`, `feat_msg.xml`, `affect_msg.xml` |
| Метка и дебаффы (типы аффектов) | `cfg/affects/affects.xml` |
| Прототипы мобов 3011–3013 | репозиторий мира, `zones/30/mobs.yaml` |

Перезагрузка на ходу: `reload animatedead` — подхватывает цифры видов для **вновь** поднимаемых
скелетов. Заклинание, класс, способность и аффекты читаются при старте сервера.

### 2. Ярус вида — что значит каждый атрибут

```xml
<creature vnum="8" id="kFierceSkeleton" spell="kAnimateSkeleton" proto_vnum="3011"
          weight="0" damroll_cap="50">
    <cost corpse_min_level="26" corpse_max_level="127" min_rating="0" />
    <scaling>
        <hp          beta="0.12"  mode="mult" cap="4.0" />
        <damage_dice beta="0.624" mode="add"  cap="33" />
        <hitroll     beta="0.3"   mode="add"  cap="30" />
        <!-- остальное beta="0" -->
    </scaling>
</creature>
```

| Атрибут | Смысл для скелетов |
|---|---|
| `spell` | Чей это ярус. `kAnimateSkeleton` уводит вид из лестницы «поднять труп»; без атрибута ярус считается нежитью (`kAnimateDead`). |
| `id` | Имя яруса. **Важно:** обработчик удара различает виды по нему — `kFierceSkeleton` (когти), `kNimbleSkeleton` (порезы), `kFetidSkeleton` (дыхание). Переименуешь — вид потеряет свой дебафф. |
| `proto_vnum` | Моб-прототип из мира. Нет его в мире — поднимается обычный скелет, в сислог ложится строка `SYSERR: 'оживить скелет': в мире нет прототипов …`. |
| `weight` | **Держать нулём.** Скелеты не тратят бюджет свиты: их число ограничено иначе — по одному каждого вида. |
| `damroll_cap` | Предел дамролла вида в автоатаке (прототип + подъём + баффы силы зла). |
| `cost corpse_min_level` | Нижняя граница уровня трупа. Труп слабее — обычный скелет. Атрибут введён для скелетов: у лестницы нежити граница только верхняя. |
| `cost corpse_max_level` | Верхняя граница; для скелетов держим `127`, то есть без ограничения сверху. |
| `cost min_rating` | Гейт по рейтингу заклинателя. У скелетов стоит `0`: настоящий ограничитель — круг способности (см. раздел 5). |
| `scaling` | Масштаб характеристик от компетентности `C` — формулы и смысл `beta`/`mode`/`cap` те же, что у нежити (разделы 7 и 8 выше). |

### 3. Как пересчитать урон вида

Доли задуманы от **суммарного урона чёрного василиска за раунд**. У василиска три атаки
(`extra_attack: 2` в прототипе) по `60d40` в пределе, то есть в среднем

```
3 × 60 × 20.5 ≈ 3690 за раунд
```

У скелетов две атаки за раунд (`extra_attack: 1`), кость `d6` (среднее 3.5). Значит нужное число
костей **на один удар**:

```
cap = доля × 3690 / (2 × 3.5)
```

`beta` подбирается так, чтобы вид выходил на свой `cap` при той же компетентности, что и василиск
(около 51):

```
beta = (cap − 1) / 51
```

Что стоит сейчас:

| вид | кубики на удар | доля от василиска | `beta` / `cap` |
|---|---|---|---|
| свирепый | 33d6 | 6.3 % | 0.624 / 33 |
| ловкий | 26d6 | 4.9 % | 0.487 / 26 |
| зловонный | 20d6 | 3.8 % | 0.370 / 20 |
| **вместе** | **79d6** | **15 %** | |

Доля не зависит от компетентности: все три `beta` пропорциональны василисковой (`1.15`), поэтому
соотношение держится и на середине роста, не только на капе. Проверять удобно так: поднять вид и
посмотреть `stat <вид> скелет` — строка «NPC сила удара» показывает текущие кубики.

### 4. Что обязательно в прототипе моба

| Поле | Зачем |
|---|---|
| `extra_attack: 1` | Две атаки за раунд. Поменяешь — пересчитывай `cap` по формуле выше. |
| `damage: 1d6` | Основа, от которой растут кубики. Размер кости менять можно, но тогда и `cap` другой. |
| `bare_hand_attack` | Тип удара в сообщениях: `8` когти («оцарапал»), `3` рубящий («рубанул»), `4` укус. |
| `kGasBreath` в `action_flags` | Только зловонному: его удар становится дыханием (магический урон вместо физического). |
| `race: 110` | Нежить. От расы зависят сопротивления и часть механик. |
| `kNoSkillTrain` | Чтобы за свиту не капали просветы. |

Метку `kBoneServant` в прототипе ставить **не нужно** — её вешает код при подъёме. Флаг в
`affect_flags` её не заменит: движок ищет действия на удар в списке аффектов, а флаг кладёт только
бит и ничего не запускает.

### 5. Доступность: круг заклинания и круг способности

В `cfg/classes/pc_necromancer.xml`:

```xml
<spell id="kAnimateSkeleton" level="26" remort="0" circle="8" mem="0" cast="0.0"/>
<feat  id="kBoneCommander"   level="1"  remort="0" slot="6"  inborn="0"/>
```

- `circle` и `level` — когда заклинание становится доступно по кругам.
- `slot` у способности — **круг способностей минус один**: `slot="6"` показывается как «Круг 7».
  Когда он открывается, считает движок: `слот = уровень × (5 + морты / remorts_for_slot) / 28`, где
  `remorts_for_slot` берётся из `<feats remorts_for_slot="…">` того же файла. У чернокнижника там
  `6`, поэтому круг 7 открывается с шестого реморта и 28 уровня.

Само заклинание игрок получает не по кругу, а из мира — гильдией, книгой или триггером
(`mspellturn`). Способность выдаётся триггером `mfeatturn`.

### 6. Дебаффы видов

Что в конфиге (`cfg/affects/affects.xml` и `messages/ru/affect_msg.xml`):

- `kBoneServant` — метка вида. Её `<actions>` объявляют `<trigger val="kPostHit"/>` и обработчик
  `SkeletonHit`. Уберёшь действие — скелеты перестанут накладывать что-либо.
- `kCorrodedArmor` («разъеденный доспех») и `kCorrodedWard` («разъеденный оберег») — сами дебаффы,
  флаги `kAfBattledec|kAfCurable` (срок в боевых раундах, лечится).
- Порезы берут готовый `kLacerations`, запрет переключения — готовый `kNoBattleSwitch`.

Что пока **в коде** (`src/gameplay/handlers/bone_commander.cpp`):

| Величина | Значение |
|---|---|
| Шаг порезки резиста | 1 % за удар |
| Потолок порезки | 12 % / 10 % / 8 % при одном, двух и трёх живых скелетах |
| Порог порезов для запрета переключения | 4 / 6 / 8 порезов при одном, двух и трёх скелетах |
| Срок дебаффа | 10 боевых раундов, продлевается каждым ударом |
| Против игроков | дебаффы не накладываются |

Сила считается в момент наложения по числу живых скелетов хозяина: погиб один — у остальных дебафф
сразу крепче, пересчитывать поднятых не нужно. Если эти цифры понадобится крутить без пересборки,
их несложно вынести в тот же `animate_dead.xml` отдельным блоком — сейчас они в коде намеренно, пока
не устоялись.

### 7. Костяная подать: нежить слабеет за свиту

issue #4032: пока у чернокнижника жив хоть один особый скелет, его нежить от «поднять труп» теряет
часть урона — и по физическому, и по магическому. Цена платится **один раз со всей свиты**: сумма
долей живых скелетов делится между всей нежитью хозяина, а не вычитается у каждой целиком. Трое
скелетов при одной нежити — те же 15 %, при двух — по 8 % каждой, при трёх — по 5 %.

Доля вида задаётся в ярусе атрибутом `damage_share` (проценты):

| вид | `damage_share` |
|---|---|
| свирепый | 6.3 |
| ловкий | 4.9 |
| зловонный | 3.8 |
| **все трое** | **15** |

Это отдельное число, а не вывод из кубиков: кубики считаются от компетентности каста и кости
прототипа, обратный пересчёт был бы хрупким. Меняешь кубики — поменяй и долю, иначе цена разойдётся
с силой.

Штраф держится аффектом **«костяная подать»** (`kBoneLevy`) на самой нежити: по строке на
`kPhysicDamagePercent` и `kMagicDamagePercent`, срок не тикает (`kAfDeadkeep`) — его ставит и
снимает код. Пересчёт происходит в трёх точках: подняли скелета, подняли нежить (она приходит уже
ослабленной) и кто-то из свиты выбыл — погиб, отпущен или кончились чары. Выбытие нежити тоже
считается: делитель меняется, и у оставшихся подать растёт. При изменении в комнату идёт строка:
«$n поник$q, отдав часть своей силы костяной свите.» или «$n расправил$u: костяная свита убыла, и
сила вернулась.».

Умертвия от «оживить труп» это не касается: подать ложится только на ярусы с `spell="kAnimateDead"`,
а умертвие поднимается по внуму трупа и в ярусах не числится.

### 8. Как проверить богом

```
featset <имя> 'костяной полководец' 1      # иначе встанет обычный скелет
skillset <имя> 'магия тьмы' 300            # компетентность каста: от неё кубики и жизни
load mob 10000                             # соловей-разбойник: 29 уровень, человекоподобный
slay соловей
колдовать 'оживить скелет' труп            # подсказка со списком видов
колдовать 'оживить скелет' труп свирепого  # вид в любом падеже
stat свирепый скелет                       # кубики, атаки, тип удара, метка в аффектах
```

Комнату брать сухую и без агрессивных мобов: заклинание требует стойки, и в бою будет «Невозможно!
Вы сражаетесь!». Дебаффы смотреть так: `приказ все убить <цель>` и ждать строк «Ядовитые когти …
разъедают доспехи …», «Смрадное дыхание … разъедает оберег …», «… затих, не в силах оторваться …».

### 9. Грабли

- **`purge` в комнате убивает и своих скелетов**, а `goto` переносит бога **без свиты** — поднимать
  надо там, где будешь воевать.
- `stat <имя>` ищет по всему миру: для жертвы берите моба с уникальным именем, иначе посмотрите
  характеристики чужого.
- Повторный подъём того же вида отказывает: «У вас уже служит …». Сперва `отпустить все`.
- Переименование `id` яруса молча отключает дебафф этого вида — обработчик различает виды по `id`.
- `weight` больше нуля заставит скелетов тратить бюджет свиты наравне с нежитью, и игрок начнёт
  упираться в чужое сообщение «Вы не сможете управлять столькими последователями».
