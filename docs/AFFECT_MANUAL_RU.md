# Bylins MUD — Руководство по конфигурации эффектов

*Для гейм-дизайнеров, описывающих эффекты в `lib/cfg/affects/affects.xml` (эффекты
персонажей) и `lib/cfg/affects/room_affects.xml` (эффекты комнат / выходов), а также
их файлы сообщений.*

**Эффект** — это длящееся воздействие на персонажа, комнату или выход: бафф,
дебафф, урон-во-времени (DoT), щит, метка призыва, статусный флаг. Если
[Руководство по заклинаниям](SPELL_MANUAL_RU.md) описывает *произнесение* (как
заклинание достигает целей и что делает *однократно*), то это руководство
описывает, что эффект делает *пока длится* и *когда с его носителем что-то
происходит*.

Раньше эффект был лишь именем + набором модификаторов статов, накладываемым одним
заклинанием, а любое поведение сверх изменения статов было зашито в C++. Сейчас
всё наоборот: **эффект владеет собственными данными** — своими флагами поведения,
модификаторами статов, весом магического щита и (главное дополнение) списком
**действий `<actions>`, управляемых триггерами**. Заклинание (или другой эффект,
или способность) лишь *накладывает* эффект; дальше эффект сам решает, что делать.

Руководство предполагает знакомство с общим словарём
[Руководства по заклинаниям](SPELL_MANUAL_RU.md) (`<damage>`, `<points>`,
`<area>`, `<affects>`, `<unaffect>`, бросок potency, перечисления
`EApply`/`ESaving`/`EResist`) — эти теги значат здесь то же самое. Новое — это
**слой триггеров/действий** (§5) и правила описания эффектов.

---

## 1. Где живут эффекты

Все данные эффектов лежат в подкаталоге **`lib/cfg/affects/`** (переехали сюда из
корня `cfg/`), файлы сообщений — в `lib/cfg/messages/<lang>/`:

| Файл | Хранит | Файл сообщений |
|---|---|---|
| `lib/cfg/affects/affects.xml` | эффекты **персонажей** (`EAffect`) | `lib/cfg/messages/<lang>/affect_msg.xml` |
| `lib/cfg/affects/room_affects.xml` | эффекты **комнат / выходов** (`ERoomAffect`) | `lib/cfg/messages/<lang>/room_affect_msg.xml` |
| `lib/cfg/affects/equipment_affects.xml` | эффекты, которые даёт **надетый** предмет (`EEquipmentAffect`) — §8.1 | `lib/cfg/messages/<lang>/equipment_affect_msg.xml` |
| `lib/cfg/affects/obj_affects.xml` | эффекты, живущие **на предмете** (`EObjAffect`) — §8.2 | `lib/cfg/messages/<lang>/obj_affect_msg.xml` |

Рядом с каждым `*.xml` лежит его `*.scheme` (для правки в Ведуне). Правьте
отслеживаемые файлы в `lib/cfg/affects` (и `lib/cfg/messages/ru`). Тестовый малый мир —
это копия, которую `tools/meson/setup_world.py` делает из `lib/cfg` в каталог `small/`
сборки; эту копию руками не редактируйте.

> **Корни файлов сообщений** приведены к имени файла (загрузчик требует
> `корень == имя == id`): `affect_msg.xml` → корень `<affect_msg>`,
> `room_affect_msg.xml` → `<room_affect_msg>` (раньше у обоих был общий
> `<msg_container>`). Кастомная копия со старым корнем **молча не загрузится** —
> переименуйте корневой тег.

**Перезагрузка.** Живьём перечитываются: `reload affects` (`affects.xml`),
`reload objaffects` (`obj_affects.xml`), `reload affectmsg` (`affect_msg.xml`),
`reload roomaffectmsg` (`room_affect_msg.xml`). У `room_affects.xml`,
`equipment_affects.xml` и файлов сообщений `equipment_affect_msg.xml` /
`obj_affect_msg.xml` отдельной цели нет — их перечитывает только `reload all`, который
перезагружает все зарегистрированные конфиги. Перезагрузка меняет то, что получат
**новые** наложения; модификаторы и флаги, уже записанные в живые экземпляры эффектов,
остаются прежними, пока эффект не наложат заново. (`reload spells` / `reload spellmsg`
/ `reload feats` — отдельные команды.)

## 2. Стыковка заклинания и эффекта

Когда `<affects><affect id="kX"/>` заклинания (§8 Руководства по заклинаниям)
срабатывает, движок строит по одному экземпляру `Affect` **на каждый apply** и
передаёт владение эффекту:

| Принадлежит **эффекту** (`affects.xml`) | Принадлежит **наложению** (блоку `<affects>` заклинания / действия) |
|---|---|
| `<flags>` — флаги поведения (`EAffFlag`) | `<duration>` — длительность |
| `<apply>` — изменения статов/статуса | сохранённый **potency** (из броска potency, с масштабом `potency_weight=`) |
| `<shield>` — вес магического щита | `saving=` / `resist=` / `prob=` — контест на наложение и шанс |
| `<actions>` — всё, что эффект делает за свою жизнь | `battleflag=` — переопределение тайминга декремента (§5.6); `<charges>` — предел срабатываний (§5.5) |

Так два заклинания могут наложить *один* эффект с разной длительностью и силой,
но **поведение** эффекта задаётся один раз, в `affects.xml`.

> **Правило.** Если эффект — «число меняется, пока эффект активен» → это `<apply>`.
> Если это «что-то происходит, *когда* случается X» (тик, удар, добивание,
> истечение, входящая атака) → это `<action>` с `<trigger>`.

## 3. Элемент `<affect>`

```xml
<affect id="kBurning" buff="N">
    <flags val="kAfSameTime|kAfDispellable"/>
    <apply location="kInitiative"><modifier .../></apply>   <!-- 0..N -->
    <shield weight="10"/>                                    <!-- опционально -->
    <actions> … </actions>                                   <!-- опционально -->
</affect>
```

### 3.1 Атрибуты заголовка

| атрибут | значение |
|---|---|
| `id` | имя из перечисления `EAffect`. Обязателен. (Эффекты комнат описываются отдельным элементом `<room_affect id=>` с именем из `ERoomAffect` — §7.) |
| `buff` | `Y` = полезный, `N` = вредный. Определяет классификацию для снятия/лечения (снятие магии убирает дебаффы, отмена — баффы) и насилие/дружелюбность повторного наложения. Нет атрибута (или `A`) = неопределённый; проверки движка сверяют с `Y`, так что неопределённый эффект считается не-баффом. Редактор Ведуна принимает только `Y`/`N`. |
| `dispel_mod` *(issue.random-noise-rework)* | Аддитивный модификатор эффекта к **порогу состязания при снятии**, в процентных пунктах (Руководство по заклинаниям §9.3). Отрицательный = **труднее** снять, положительный = легче. По умолчанию `0`. Критические баффы (огне/ледо/возд. щит, магическое зеркало, стихийные ауры, санктуарий, призм. аура, полёт, водное дыхание и ещё несколько) поставляются с `dispel_mod="-35"` → ~15 % на снятие при равной компетентности против ~50 % обычного бафа. |

Эффект может существовать с **пустым телом** (`<affect id="kCommander"/>`) — как
чистая метка-флаг, которую проверяет другой код. Добавление данных это не ломает.

## 4. Пассивные слои: `<flags>`, `<apply>`, `<shield>`

### 4.1 `<flags val="A|B|…">` — биты поведения `EAffFlag`

Биты тайминга декремента решают, **когда убывает длительность** — это самое
важное, потому что заодно решает, *какие циклы триггеров видят эффект*:

| флаг | длительность убывает… |
|---|---|
| *(нет)* | раз в **игровой час** (обновление вне боя). |
| `kAfBattledec` | раз в **боевой раунд**, пока носитель сражается (боевое обновление). |
| `kAfPulsedec` | раз в **пульс** эффектов (быстрый цикл мобов/коротких баффов). |
| `kAfSameTime` | раз в 2 с у игрока, раз в минуту у NPC или в такт боевому раунду в бою (для урона-во-времени). |

Прочие частые биты:

| флаг | эффект |
|---|---|
| `kAfDispellable` | снимается развеиванием магии / отменой. |
| `kAfCurable` | снимается лечащими заклинаниями / первой помощью. |
| `kAfUpdateDuration` | повторное наложение обновляет длительность до **большей** (вместо второго экземпляра). |
| `kAfAccumulateDuration` | повторное наложение **складывает** длительности. |
| `kAfUpdateMod` | повторное наложение сохраняет **больший** модификатор. |
| `kAfDeadkeep` | эффект переживает смерть носителя. |
| `kAfMaterialize` | эффект можно материализовать как врождённый бафф моба (бросок от одноимённого заклинания). |
| `kAfEntanglement` | категория «ограничение движения» (её проверяют приёмы работы ног, а не конкретное заклинание). |
| `kAfPoison` | категория «яд» (механики «все яды» проверяют этот флаг). |
| `kAfBoon` / `kAfWarding` / `kAfAegis` | классы баффов для снятий по классу (`<unaffect affect_flags="kAfBoon">` и т. п.): мелкие полезные / обычные боевые / сильная защитная магия. |
| `kAfFullAbsorb` | полная неуязвимость к урону (магический кокон, `kGodsShield`). |
| `kAfNoPositionBonus` / `kAfNoCritBonus` | пока это активный щит, атакующий не получает бонуса за низкую позицию / за крит (воздушный / ледяной щит). |

Полный список — в `src/gameplay/affects/affect_contants.h`. Часть битов **не**
для `affects.xml`: `kAfFromEquipment`, `kAfFromSet`, `kAfCharmBond`, `kAfFailed` движок
ставит на отдельные экземпляры, а `kAfNeedControl`,
`kAfCasterInRoom`/`kAfCasterInWorld`/`kAfCasterInWorldDelay`, `kAfUnique`,
`kAfMustBeHandled` относятся к эффектам комнат (§7).

> **Мультиэкземплярность.** Заклинание, накладывающее эффект с несколькими
> `<apply>`, создаёт **несколько экземпляров** (по одному на apply) с общей
> длительностью, истекающих вместе. Это важно для триггеров `kExpired`/`kDeath` —
> см. §5.5.

### 4.2 `<apply>` — изменения статов/статуса, принадлежащие эффекту

```xml
<apply location="kInitiative">
    <modifier min="0" beta="0.4143" factor="1"/>
</apply>
```

`location` — это `EApply` (`kHitroll`, `kAc`, `kInitiative`, `kSavingReflex`, …).
Формула `<modifier>` (`ComputeApplyModifier`, общая для apply заклинаний и эффектов):

```
raw = min + ceil(beta·C·(1 + weight·d))      C = skill_coeff + stat_coeff, d = шумовой бросок каста
raw = min(raw, cap)                          (только при cap > 0)
modifier = factor · raw                      (factor = -1 для дебаффов)
```

| атрибут `<modifier>` | по умолч. | значение |
|---|---|---|
| `min` | `0` | плоская база. |
| `beta` | `0` | вес компетентности. |
| `weight` | `0` | вес случайного шумового броска каста; `0` = детерминированно (так у всех эффектов в игре). |
| `factor` | `1` | знак/множитель; `-1` для дебаффов. |
| `cap` | `0` | предел величины до умножения на `factor`; `0` = без предела. |
| `stack` | `1` | предел стаков (§4.2.2). |

**`C` (компетентность) даёт то, что накладывает эффект** (§3.7 Руководства по
заклинаниям). Реальное произнесение заполняет `C` из своего броска potency (навык +
стат). *Триггерное действие эффекта* (§5) берёт `C` из **сохранённого potency
сработавшего эффекта** — так эффект может наложить другой эффект, масштабирующийся от
силы первого (так масштабируется хасте-за-добивание у вампиризма, §9). Плоский эффект
использует только `min` (`beta=0`).

> **Эффект владеет своими apply.** Если эффект задаёт `<apply>`, каждое
> накладывающее его заклинание использует *их* (собственные apply заклинания
> игнорируются). Давайте apply эффекту; на заклинании оставляйте лишь
> `<duration>`/`saving`/`resist`. Старые эффекты без `<apply>` по-прежнему
> откатываются к apply заклинания.

#### 4.2.1 Настройка модификаторов через компетентность *(правила `beta`)*

Величина модификатора должна расти от **компетентности кастера (навык + стат)**, а
не напрямую от уровня/ремортов. Модификаторы детерминированы (`weight=0`), так что
формула сводится к `min + ceil(beta·C)`, где `beta` — аддитивный вес компетентности.

Перевод из СТАРОЙ формулы по уровню/реморту:

> **1 реморт ≈ +5 к кэпу навыка + +1 к базовому стату** (`lib/cfg/remort.xml`: кэп
> навыка `increment="5"`). Выше порога новичка каждое очко навыка стоит
> `hi_skill_bonus`, так что компетентность растёт на
> `(5·hi_skill_bonus + 1·вес_стата)/100` за реморт. Для типового броска potency
> (`low_skill_bonus=1 hi_skill_bonus=7`, стат `threshold=22 weight=18`) это
> `(5·7 + 1·18)/100 = 0.53` за реморт. Значит модификатору, который должен расти на
> `k` за реморт, нужен `beta ≈ k / 0.53`.

Два правила:

* **`min ≥ 0`.** Подбирайте `min`/`beta` так, чтобы нетренированный кастер (`C=0`)
  получал `min·factor` (0 или чистую базу) — никогда не позволяйте дебаффу с
  `factor="-1"` инвертироваться в бафф для слабого кастера. Если агрессивный бросок
  potency вынуждает `min<0`, уменьшите `beta` или нормализуйте бросок; некоторые
  эффекты намеренно остаются плоскими (`beta=0`, напр. `kPatronage`).
* **Якорь типового кастера.** Возьмите `beta ≈ |цель при R12 макс-навык| / C_R12`
  (округляя *вниз*, чтобы `min≥0`), затем `min = |цель при R12| − ceil(C_R12·beta)`.
  Пример — `kBless` поставляется с `min=0 beta=1.2889 factor=-1` на `kSavingStability`
  (и `beta=1.1508` на `kSavingWill`).

#### 4.2.2 Стакирование

`<modifier stack="N"/>` ограничивает число стаков одного apply на цели. При
`stack="1"` (по умолчанию) повторное наложение обновляет/отклоняется по флагам
`kAfUpdate…`. При `stack>1` повторное наложение **добавляет стак** (накапливая
модификатор до `N·mod`, продлевая длительность при
`kAfAccumulateDuration`/`kAfUpdateDuration`). При развеивании снимается **один
стак** (модификатор пропорционально уменьшается), а не весь эффект — эффект
исчезает лишь со снятием последнего стака. Так «накапливающийся яд / нарастающий
дебафф» становится чистыми данными.

#### 4.2.3 Случайные пулы apply

Среди соседних apply с флагом `<apply … random="Y">` за одно наложение выбирается
**ровно один** (равновероятно). Безусловные apply срабатывают всегда; случайные
делят один пул. Пример `kFailure`: один гарантированный штраф морали + один
случайный штраф стата из шести.

### 4.3 `<shield weight="N"/>`

Для семейства магических щитов (огонь/лёд/воздух): относительный вес, с которым
именно этот щит выбирается перехватить входящий удар, когда у носителя их
несколько. Имеет смысл только вместе с действиями щита на `kWardDamage`
(`<retaliation>` / `<damage_change>`, §5.4).

## 5. `<actions>` — слой триггеров *(новое ядро)*

`<actions>` эффекта — упорядоченный список блоков `<action>`. Каждый несёт
`<trigger>`, задающий **когда** он срабатывает, и одно или несколько **проявлений
эффекта**, задающих **что** он делает. Это тот же словарь действий, что у
`<talent_actions>` заклинания (§3.8 Руководства по заклинаниям) — `<damage>`,
`<points>`, `<affects>`, `<unaffect>`, `<side_spell>`, `<manual_cast>`, `<area>` — плюс
проявления-щиты `<damage_change>`, `<retaliation>`, `<reflection>`, `<absorption>`,
которые читают триггеры `kWardDamage` / `kWardAttack` (§5.4).

```xml
<actions>
    <action target="kTarFightSelf" base="tag" tag="amount">
        <trigger val="kPostHit"/>
        <points extra="100"><heal npc_coeff="0" min="1" beta="0.1" weight="0"/></points>
    </action>
</actions>
```

### 5.1 Набор триггеров (`<trigger val="…">`)

| триггер | срабатывает, когда… | типичное применение | актор / примечания |
|---|---|---|---|
| `kPulse` | каждый пульс эффектов, в бою и вне | DoT / HoT / периодический эффект | без актора |
| `kBattlePulse` | пульс эффектов, **только пока в комнате идёт бой** | боевой DoT | без актора |
| `kPreHit` | носитель наносит удар (замах, до урона) | наездник-на-замахе | событие: оружие, навык |
| `kPostHit` | удар разрешился (после урона) | вампиризм, прок-на-удар | событие: amount, оружие, навык, actor=жертва |
| `kKill` | носитель нанёс **смертельный** удар (прямой или через DoT) | награда за добивание | actor=жертва (мертва — **не** целить в неё); цели `kTarFightSelf`/`kTarGroup` |
| `kExpired` | таймер/заряды эффекта истекли | эффект-при-спадении | без внешнего актора; цели на себя/союзников |
| `kDispell` | эффект **принудительно** снят (развеивание/отмена) | ужалить развеивающего | actor = развеивающий (`kTarActor`) |
| `kDeath` | носитель умирает (до окончательной смерти) | предотвращение смерти | actor=убийца; `<trigger return="0"/>` + самолечение *предотвращают* смерть |
| `kPoints` | носителя **восстановил** внешний кастер | реакция на лечение | actor=лекарь; `category=` фильтрует kHeal/kMoves/kThirst/kFull |
| `kWardDamage` | **входящий** экземпляр урона на носителе | пассивное изменение урона (санктуарий, призма) | см. §5.4 |
| `kWardAttack` | носитель — **цель** входящей (магической) атаки | отражение / поглощение произнесения | срабатывает раз за произнесение на входном гейте |
| `kEnter` / `kEnterPC` / `kEnterNPC` | вход персонажа / игрока / NPC (эффекты комнат) | эффект-при-входе / печать | actor = вошедший (`kTarActor`); `return="0"` запрещает вход |
| `kPick`/`kUnlock`/`kOpen`/`kClose`/`kLock` | команды с дверью (эффекты выходов) | ловушки / запечатанные двери | `return="0"` запрещает действие |

У эффектов на предметах есть свои триггеры (`kWeaponHit`, `kGet`/`kDrop`/`kEquip`/`kUnequip`/`kDecay`) — §8.2.

### 5.2 Атрибуты `<action>`

| атрибут | значение |
|---|---|
| `target` | `EActionTarget` (§5.3), по умолчанию `kTarSame`. На кого ложится эффект действия. |
| `base` | как масштабируется величина: по умолчанию `kCompetence` (potency); `tag` = значение из события; `kDamage`/`kPoints`/`kAffects`/`kDispelled` = результат прошлого действия (§3.8.2 Руководства по заклинаниям). |
| `tag` | при `base="tag"` — поле события (напр. `amount` = нанесённый/восстановленный объём). |
| `reset` | `Y`/`true` — сброс цепочки (§3.8.2 Руководства по заклинаниям). |
| `id` | постоянное имя блока, по которому его патчат способности (§9, `kSoulLink`). |

Податрибуты `<trigger>`: `val` (обязателен; можно несколько через `|`), `category`
(фильтр kPoints), `return` (`"0"` = блокировать вызвавшее действие — для `kDeath`,
`kEnter*`, дверных триггеров), `prob` (шанс срабатывания).

### 5.3 Цели (`EActionTarget`)

`kTarSame` (цели предыдущего действия), `kTarFightSelf` (носитель),
`kTarFightVict` (противник носителя), `kTarGroup` / `kTarFoes` (нужен `<area>`),
`kTarRandomFoe` / `kTarRandomAlly`, `kTarMinions` (очарованные последователи),
`kTarActor` (вызвавший событие — вошедший / развеивающий / лекарь),
`kTarMaster` (хозяин очарования носителя — для эффектов на стороне хозяина, как
kSoulLink), `kTarRoomThis` (сама комната).

### 5.4 Проявления эффекта

Внутри `<action>` — те же стадии, что у заклинания (§5–8 Руководства по
заклинаниям), плюс:

* `<damage>` — нанести урон (`<amount min= beta= weight=>`; `<damage>` на
  `kPulse`/`kBattlePulse` — это **DoT**, масштабируемый от сохранённого potency через
  `beta`). Дайте эффекту свои сообщения `kDamageToChar/Vict/Room` (§6), иначе DoT
  будет молчаливым.
* `<points><heal>` — восстановить HP/движение (`kPulse`-лечение — это **HoT**;
  лечение на `kPostHit` — вампиризм, масштабируется от `base="tag" tag="amount"`).
* `<affects>` — наложить другой эффект (см. §5.6 про контроль длительности/флагов).
* `<unaffect>` — развеять/вылечить (грамматика §9 Руководства по заклинаниям).
* `<side_spell id="…">` — произнести целое заклинание как вложенный эффект.
* `<manual_cast handler="…">` — зашитый обработчик (выбор — данные; тело — C++).
* `<damage_change>` — **`kWardDamage`**: пассивно масштабировать/править входящий
  экземпляр урона. Структура:
  ```xml
  <damage_change>                             <!-- опционально: prob=, stage="late", msg="crit|none" -->
      <conditions>
          <type val="kPhysDmg"/>              <!-- kPhysDmg / kMagicDmg / kPoisonDmg / kPureDmg / kUndefDmg -->
          <flags missing="kIgnoreSanct"/>     <!-- пропустить, если удар игнорирует щит; есть и present= -->
      </conditions>
      <variation min="50" max="50" factor="-1"/>   <!-- здесь -50% -->
      <flags add="kShieldApplied"/>                <!-- опционально: правка флагов удара (add= / remove=) -->
  </damage_change>
  ```
* `<retaliation>` — **`kWardDamage`**: отразить процент удара обратно атакующему
  (`<conditions>`, `<percent min= max= npc_bonus= boss_bonus=>`, `<element type=>`;
  опционально `passive=`, `prob=`).
* `<reflection>` / `<absorption>` — **`kWardAttack`**: отскок / поглощение входящего
  произнесения (`<reflection min= max=>` — состязание; `<absorption scope="all|damage|affect"
  chance= prob=>`).

Ими перенесли старую зашитую логику санктуария/призмы/огнещита — копируйте
существующий эффект-щит как шаблон.

### 5.5 `<charges max="N"/>` — ограниченные срабатывания

**Триггерный** эффект может нести `<charges max="N"/>` внутри блока `<affects>`,
который его накладывает (в `spells.xml`, `room_affects.xml` или в другом действии — но
не в собственной записи `<affect>`): эффект снимается после `N` срабатываний,
независимо от длительности. `-1` (по умолчанию) — без ограничения (только по
длительности). DoT с `<charges max="7"/>` тикает ровно 7 раз (так `kFireBlast`
накладывает `kBurning`). Сочетайте с действием `kExpired`, чтобы отреагировать на
исчерпание зарядов.

> **Дедупликация.** DoT на `kPulse` и триггеры жизненного цикла (`kExpired`)
> срабатывают **один раз на тип эффекта за проход**, даже если у эффекта несколько
> экземпляров (мультиэкземплярные эффекты). Описывайте действие при
> истечении/тике один раз — оно не сработает дважды.

### 5.6 Контроль длительности и флагов у накладывающего `<affects>`

Когда действие эффекта накладывает другой эффект, его блок `<affects>` управляет
новым экземпляром:

* `<duration base="…" skill_divisor="…" min="…" max="…" skill="kX"/>` — формула
  длительности (§8.2 Руководства по заклинаниям). Атрибут **`skill="kX"`**
  специфичен для действий эффекта: у триггерного действия нет заклинания-источника,
  поэтому оно называет навык, чей бонус-новичка масштабирует длительность
  (например, похмелье, масштабируемое от `kHangovering`). Без `skill=` триггерное
  действие не масштабирует длительность по навыку.
* `battleflag="kAfBattledec|…"` — добавить (OR) флаги тайминга декремента новому
  экземпляру. Так действие может выдать обычно многочасовой эффект как короткий,
  **измеряемый в боевых раундах**: при `kAfBattledec` `<duration>` читается как
  **сырые боевые раунды** (без пересчёта часы→тики для игрока). Так вампиризм
  выдаёт хасте-за-добивание (§9) на 5–6 раундов.

## 6. Сообщения

Тексты эффектов лежат в `lib/cfg/messages/<lang>/affect_msg.xml` (и
`room_affect_msg.xml`), с ключами на каждый id эффекта (`<msg_sheaf id="kX">`, плюс
общий набор `kDefault`). Движок читает ключи:

| семейство ключей | показывается, когда |
|---|---|
| `kAffImposedToChar/Vict/Room`, `kAffImposeFailToChar/Vict/Room` | эффект наложился / не наложился |
| `kAffExpiredToChar/Room` | эффект спал (kExpired) |
| `kAffExpireSoon` | комнате на последнем тике эффекта у NPC перед его спадением |
| `kAffDispelledToChar/Room` | эффект развеян (kDispell) |
| `kDamageToChar/Vict/Room` | сработало действие `<damage>` (дайте это DoT, иначе он молчит) |
| `kWardToChar/Vict/Room` | щит перехватил (kWardDamage/kWardAttack) |
| `kDeathToChar/Room` | сработало действие `kDeath` |
| `kTransformToChar/Vict/Room`, `kTransformCrit…` | флейвор трансформации/полиморфа |
| `kShortDesc`, `kLook`/`kLookPoly`, `kShieldFrame`/`kShieldNoun…`, `kAuraFrame`/`kAuraNoun…` | отображение: короткое имя эффекта (списки эффектов, опознание), строка при осмотре носителя и общая строка щитов/аур |

Пустой ключ = стандартная строка движка (или тишина, для урона). Заполняйте хотя
бы наложение/спадение и любые ключи урона.

## 7. Эффекты комнат и выходов (`room_affects.xml`)

Эффекты комнат/выходов — это записи `<room_affect id="…">` (имя из `ERoomAffect`) под
корнем `<room_affects>`. Они используют ту же грамматику `<flags>`/`<actions>`, но
добавляют:

* **Триггеры входа и дверей** — `kEnter`/`kEnterPC`/`kEnterNPC` и
  `kPick`/`kUnlock`/`kOpen`/`kClose`/`kLock`. `<trigger return="0"/>` **запрещает**
  вход/действие с дверью (запечатанная комната, ловушка на замке). `kTarActor` =
  вошедший.
* **`<area>` + `<targets>` + `<distribution>`** — действие комнаты может задеть
  всех в комнате с затуханием по целям (грамматика §7 Руководства по заклинаниям).
* **Потиковый эффект — это действие** — действие на `kPulse` несёт либо
  `<side_spell>` (обычное заклинание, как правило на `kTarFoes` с `<area>`), либо
  `<manual_cast>` (зашитый обработчик, напр. `kThunderstorm`). Это заменило прежние
  отдельные tick-заклинание и tick-обработчик.
* **`<target_conditions>`** — гейт действия по вошедшему/комнате (blocking/required).
* **`<seal_strength min= beta= factor= cap=>`** — формула силы печати у запечатывающего
  эффекта (`kForbidden`), видна звёздочками при осмотре.
* **Флаги эффектов комнат** — `kAfNeedControl`, `kAfCasterInRoom`, `kAfCasterInWorld`,
  `kAfCasterInWorldDelay`, `kAfUnique` (§4.1).

## 8. Эффекты предметов *(новое ядро — issue.equipment-affects / issue.obj-affects)*

Помимо эффектов персонажей (§3–6) и комнат (§7) есть два класса эффектов, связанных
с **предметами**:

* **Эффекты снаряжения** (`equipment_affects.xml`, §8.1) — то, что даёт **надетый**
  предмет своему носителю (невидимость, полёт, огнещит; а также дебаффы проклятого
  шмота). Живут на **персонаже**, пока предмет надет.
* **Эффекты на предмете** (`obj_affects.xml`, §8.2) — эффекты, живущие **на самом
  предмете** (яд на оружии, благословение/проклятие, ловушка).

### 8.1 Эффекты снаряжения (`equipment_affects.xml`)

Исторически это был набор флагов «weapon affect» (`EWeaponAffect`) — название вводило
в заблуждение: их даёт **любой** надетый предмет, не только оружие. Механику
переименовали (`EEquipmentAffect`) и перевели на данные. Каждая запись — токен
`EEquipmentAffect` (идентичность) с одним потомком `<impose>`:

```xml
<equipment_affects>
    <affect id="kInvisibility">
        <impose flag="kInvisible" spell="kUndefined" timer="-1" power_percent="60"/>
    </affect>
    <affect id="kBlindness">
        <impose flag="kUndefined" spell="kBlindness" power_percent="60"/>
    </affect>
    <affect id="kFireShield">
        <impose flag="kFireShield" spell="kUndefined" timer="-1" power_percent="60"/>
    </affect>
</equipment_affects>
```

| Атрибут `<impose>` | Значение |
|---|---|
| `flag` | `EAffect`-бит, выставляемый носителю (`kUndefined` = нет; эффект задаётся заклинанием). |
| `spell` | `ESpell`, кастуемое при надевании (`kUndefined` = нет). |
| `timer` | Длительность в тиках; **`-1` = постоянно, пока надет**; **отсутствует = временный/по заклинанию** (дебаффы слепота/сон/удержание/яд держатся, лишь пока предмет надет, и спадают мгновенно при снятии — постоянного надетого «сна» быть не должно). |
| `power_percent` | Процент масштабирования силы, подаётся в конвейер потенции (ниже). По умолчанию `100`. |

Два идиома: **постоянный бафф** (`flag="kX" spell="kUndefined" timer="-1"`) и
**дебафф проклятого предмета** (`flag="kUndefined" spell="kBlindness"` без `timer`).

**Материализация и сила.** Раньше эффекты снаряжения были флагами, перевыводимыми на
каждом `affect_total` (без силы, неснимаемые). Теперь при надевании
`MaterializeEquipmentAffects` добавляет по одному **настоящему `Affect`** на запись, у
которой заданы и `timer`, и `flag`, помеченному флагом **`kAfFromEquipment`** и
`caster_id` = id предмета; при снятии `RemoveEquipmentAffects` их убирает (в файл игрока
такие эффекты **не пишутся** — они пере-материализуются при надевании). Сила больше не
берётся из жёсткой таблицы (`GetApplyByEquipmentAffect` удалён): `<apply>`/`<modifier>`
эффекта живут в `affects.xml`, а величина выводится из предмета (уровень предмета →
навык и стат, масштаб `power_percent`) и прогоняется через **тот же конвейер потенции,
что и каст** — детерминированно (шум 0: бонус предмета фиксирован). Благодаря этому у
эффекта снаряжения наконец есть осмысленная **сила для состязания при снятии** (была 0).

Эффекты от **комплектов** (сетов) объединены под тем же механизмом: флаг
**`kAfFromSet`** помечает эффект, материализованный активным сетом
(`reconcile_set_affects`); он принадлежит сету, а не одному предмету.

> **Сопротивления, а не эффекты.** `kProtectFromDark` / `kProtectFromMind` (биты 11–12)
> **сняты** из `EEquipmentAffect`: это числовые параметры сопротивления, а не
> вкл/выкл-эффекты. Давайте их предмету напрямую через apply —
> **`EApply::kResistDark` / `EApply::kResistMind`**. Биты 11–12 **зарезервированы, не
> переиспользуйте** (старые данные предметов остаются валидными; в OLC слоты видны как
> `UNUSED`).

### 8.2 Эффекты на предмете (`obj_affects.xml`)

Эффект, живущий **на предмете** (не на персонаже), со своей идентичностью
`obj_affects::EObjAffect` (независимо от `ESpell`/`EAffect`); материализуется как
настоящий `Affect<EObjApply>` в списке эффектов предмета. Файл-реестр короткий:

```xml
<obj_affects>
    <obj_affect id="kInvisible" flag="kInvisible" msg_case="kGen" see_affect="kDetectInvisible"/>
    <obj_affect id="kCurse"     flag="kNodrop"    msg_case="kGen" see_affect="kDetectMagic"/>
    <obj_affect id="kPoisoned" msg_case="kGen" see_affect="kDetectMagic">
        <actions>
            <action target="kTarActor">
                <trigger val="kWeaponHit"/>
                <manual_cast handler="WeaponPoisonHit"/>
            </action>
        </actions>
    </obj_affect>
    <obj_affect id="kBless" flag="kBless"   msg_case="kAcc" see_affect="kDetectMagic"/>
    <obj_affect id="kFly"   flag="kFlying"  msg_case="kGen" see_affect="kUndefined"/>
    <obj_affect id="kLight" flag="kGlow"    msg_case="kGen" see_affect="kUndefined"/>
    <obj_affect id="kDartTrap" see_affect="kDetectMagic">
        <actions>
            <action target="kTarActor">
                <trigger val="kPick|kOpen" return="0"/>
                <damage saving="kNone"><amount min="200" beta="0" weight="0"/></damage>
                <side_spell id="kPoison"/>
            </action>
        </actions>
    </obj_affect>
    <obj_affect id="kSuppressed" dispellable="0" see_affect="kUndefined"/>
</obj_affects>
```

| Атрибут | Значение |
|---|---|
| `id` | Токен `EObjAffect` (идентичность). |
| `flag` | `EObjFlag`, которым эффект **владеет**, пока активен: ставится на **экземпляр** предмета при наложении, снимается при спадении **только если у ПРОТОТИПА такого флага нет** (врождённый флаг прототипа постоянен). Пусто = своего флага нет (напр. `kPoisoned` читает яд из самого эффекта). |
| `dispellable` | `0/1` (по умолч. `1`): может ли игровой эффект (снять проклятие / рассеять магию / тьма) снять этот эффект. Правило врождённого флага прототипа действует всегда отдельно. `kSuppressed` = `0`. |
| `msg_case` | Падеж имени предмета (`%s`) в сообщениях жизненного цикла: `kNom/kGen/kDat/kAcc/kIns/kPre` (по умолч. `kGen`). |
| `see_affect` | Какой `EAffect` нужен осматривающему, чтобы **увидеть** эффект (`kUndefined` = виден всегда, напр. полёт/свет; иммы и god-`stat` — всегда). |
| `<actions>` | Тот же репертуар `talents_actions`, что у эффектов комнат, плюс obj-триггеры (ниже). |

**Новые obj-триггеры:** `kWeaponHit` (предмет-оружие нанёс удар — так работает
**яд-при-ударе**: `kPoisoned` → `<manual_cast handler="WeaponPoisonHit">` на
`kTarActor` = жертве удара) и триггеры жизненного цикла предмета
`kGet`/`kDrop`/`kEquip`/`kUnequip`/`kDecay`. Ловушка **`kDartTrap`** срабатывает на
`kPick|kOpen` с `return="0"` (**блокирует** вскрытие), наносит `<damage>` (impersonal —
без атакующего) и `<side_spell id="kPoison">` актору, потревожившему её.

Сериализация: блок `OAff:`, по строке `<токен> <таймер> <модификатор> <сила>` на
эффект, закрытый `~` (4-е поле — сила, для подавлений; старые 3-полевые строки
читаются с силой 0). Легаси `TSpl:` (timed-spell) читается и маппится на `EObjAffect`
(4 яда → `kPoisoned`; благословение/полёт/свет → `kBless`/`kFly`/`kLight`). **Мир не
конвертируется** — это формат файлов предметов игроков, обратно совместимый.

### 8.3 Подавление и восстановление *(issue.obj-suppressor-affect / issue.affect-suppression-dispell)*

Развеивание эффекта снаряжения раньше теряло его до пере-надевания. Теперь эффект
**подавляется на своём предмете-источнике** на время и **авто-возвращается** по
истечении:

* Диспелл эффекта с `kAfFromEquipment` вызывает `SuppressSourceEquipmentAffect`:
  находит предмет-источник (по `caster_id`) среди надетого и подавляет на нём эффект на
  **10 игровых часов**; сам эффект снимается сразу (бафф спадает **сейчас**), а носителю
  сообщают, когда волшебство вернётся. У эффекта от сета (`kAfFromSet`) единственного
  владельца нет, поэтому подавление получает каждый надетый предмет сета.
* Подавление — это **obj-эффект `kSuppressed`** (один на подавленный `EAffect`),
  поэтому сериализуется и тикает как прочие obj-эффекты. Оно **хранит силу** =
  компетентность подавившего диспелла (сопротивление для будущего снятия; при
  повторном подавлении берётся **МАКС**).
* **Оффлайн — на паузе:** оффлайн-докрутка (рент/релог) пропускает `kSuppressed`
  (иначе оно истекло бы за оффлайн и бафф вернулся при входе). Прочие obj-эффекты
  (яд-DoT, ловушки) продолжают тикать оффлайн.
* По истечении таймера (или досрочно — заклинанием) эффект снаряжения
  **авто-возвращается** на носителя.

**Снятие досрочно — заклинание `восстановить плетение` (`kWeaveRestoration`).** Новое
магское заклинание (маг, круг 4), которое **состязается**, чтобы снять подавление и
вернуть эффект раньше. Кастуется на предмет (в инвентаре или на земле) или на
персонажа (тогда бьёт по **случайному** надетому предмету жертвы с подавлением).
Механика состязания `DispelContest` — в §9.3.1 Руководства по заклинаниям (сила
подавления берётся напрямую, без `dispel_mod`; бросок делается всегда; при промахе
подавление изнашивается на `decay`%). Грамматика действия —
`<alter_obj handler="AlterWeaveRestore" collateral="first_suppressed" dispel_bonus= decay= bypass_noalter=>` (там же).

**Отображение подавления** — четыре поверхности осмотра:

* В списках предметов (`экипировка` и т. п.) у предмета появляется компактная метка
  ` <магия подавлена>`.
* На `осмотреть` — заголовок и отступ-колонка:
  ```
  Временно подавлено волшебство:
      летит (8 часов)
      доблесть (6 часов)
  ```
* На `опознать` — та же колонка под заголовком `Временно подавлены     :`.
* В god-`stat` — одна строка: `Подавленные аффекты   : летит (8 часов), …`.
* Время — в **игровых часах** (счётчик тикает раз в MUD-час).

Смежные правки: развеиваемые баффы теперь используют **своё** сообщение снятия
(цепочка `kAffDispelled` → `kAffExpired` → `kDefault`, а не общее «Волна тепла…»);
постоянный эффект (`duration < 0`) в `аффекты` показывается как «(постоянно)».

## 9. Разобранные примеры (все в игре)

* **DoT — `kBurning`:** `kAfSameTime` + действие `kPulse`
  `<action target="kTarFightSelf">` с `<damage saving="kNone"><amount min="1" beta="6"
  weight="0"/>`, масштабируемым от сохранённого potency, плюс сообщения `kDamageTo*`.
  Тикает в бою и вне; ограничен `<charges max="7"/>` накладывающего (`kFireBlast`,
  ответный ожог при развеивании `kFireTrap`).
* **Вампиризм + добивание — `kVampirism`:** `kPostHit`
  `<points><heal base="tag" tag="amount" min="1" beta="0.1">` (лечит 10% нанесённого
  урона) **и** `kKill` `<affects battleflag="kAfBattledec"><duration base="6">
  <affect id="kHaste"/>` — короткий боевой хасте в награду за добивание.
* **Бафф/дебафф стата — `kHaste`/`kSlowdown`:** один
  `<apply location="kInitiative">` (`beta=0.4143`, `factor=+1`/`-1`) — масштаб от
  навыка кастера; пара складывается (итог = сумма), т.к. оба пишут в один `EApply`.
* **Щит — `kSanctuary`/`kFireShield`:** `kWardDamage` `<damage_change>` блоки
  (−50% физ / +100% маг для санктуария); огнещит добавляет действие `<retaliation>`
  (отражает 15 %) и поздние (`stage="late"`) снижения на 30–50 %.
* **Цепочка при спадении — `kDrunked` → `kAbstinent`:** `kExpired`
  `<action target="kTarFightSelf"><affects><duration … skill="kHangovering"/>
  <affect id="kAbstinent"/>` — естественное протрезвление оставляет похмелье,
  масштабируемое по навыку (kAbstinent владеет своими apply на AC/HR/DR).
* **Эффект, изменённый способностью — `kSoulLink`:** *способность* патчит
  `kVampirism`, чтобы лечить ещё и хозяина миньона (`kTarMaster`). Патчинг на
  стороне способности — в [Руководстве по способностям](FEAT_MANUAL_RU.md); сам
  эффект не трогается.

## 11. Чек-лист для добавления / миграции эффекта

1. **Добавьте / найдите id `EAffect`** и его блок `<affect id= buff=>`.
2. **Пассивная часть → `<apply>`** (владейте apply; `<duration>` — на накладывающем).
3. **Выберите флаги декремента** (`kAfBattledec` для эффектов на боевые раунды;
   ничего — для многочасовых баффов) — это решает и то, какие циклы триггеров его
   видят.
4. **Поведенческая часть → `<actions>`**: выберите `<trigger>`, `target` и
   проявление (`<damage>` DoT / `<points>` HoT / `<affects>` наложение /
   `<damage_change>` щит). Масштабируйте через `base="tag"` или potency (`beta`).
5. **Сообщения** — хотя бы наложение/спадение плюс `kDamageTo*` для любого DoT.
6. **Эффект комнаты?** поместите в `room_affects.xml` как `<room_affect>` и
   рассмотрите триггеры входа/дверей.
7. **Уберите зашитый C++**, который эффект заменяет (оставьте id как метку, если
   другой код всё ещё проверяет флаг).
8. **Проверьте** в mud-sim: наложите, протикайте/триггерните, подтвердите эффект +
   сообщения (учтите: sim прокручивает циклы боевых раундов, но не почасовое
   обновление — используйте `kAfBattledec`, чтобы наблюдать триггеры по истечению).
9. **Эффект предмета?** это отдельные подсистемы — надетый-предмет → §8.1
   (`equipment_affects.xml`), эффект на предмете → §8.2 (`obj_affects.xml`).
